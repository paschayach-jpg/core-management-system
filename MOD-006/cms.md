## 🛠 Technical Stack
For development in an environment that emphasizes stability and supports legacy systems in the insurance industry, the following stack is used:

- **Framework:** .NET Framework 4.5 (C#)  
- **UI Library:** Windows Forms (WinForms)  
- **Database:** Microsoft SQL Server 2019  
- **Data Access:** **ADO.NET** (Raw SQL / Stored Procedures)  
  - *Note: Optimized for high-performance data retrieval and supports `Thai_CI_AS` collation*

## 🏗 System Design Pattern (Layered Architecture)
The system is designed using **Separation of Concerns** by dividing responsibilities into 4 main layers to ensure maintainability and support unit testing:

### 1. 🖥 CMS.Presentation (UI Layer)
The layer that directly interacts with users (User Interface)

- **Structure:** Separated into `VisualDesigner.cs` and `CodeBehind.cs` (UI Logic / Event Handling)  
- **Responsibility:** Display data and receive user input without containing business logic  

---

### 2. 🎮 CMS.Controllers (Orchestration Layer)
The intermediary between UI and business logic

- **Responsibility:** Receives requests from the Presentation layer and determines which **Service** should handle the operation, ensuring the UI is decoupled from internal logic  

---

### 3. 🧠 CMS.Services (Business Logic Layer)
**"The brain of the system"**

- **Responsibility:** Handles all core business logic such as:
  - Premium calculation  
  - Coverage validation  
  - Approval workflow management  

---

### 4. 📦 CMS.Repository (Data Access Layer)
**"The data retriever"**

- **Responsibility:** Handles CRUD (Create, Read, Update, Delete) operations with SQL Server using ADO.NET  
- This is the only layer that interacts directly with SQL commands or stored procedures  

---

## 📝 Developer Coding Standards

1. **Strictly No ORM:**  
   Only ADO.NET is used to ensure optimal performance for complex insurance data queries  

2. **Naming Convention:**  
   Use PascalCase for methods and class names  

3. **Audit Logs:**  
   All CRUD operations in the Repository layer must include user stamping (audit trail) to comply with OIC (Office of Insurance Commission) security standards
