ภาพรวม ฟีเจอร์หลัก สถาปัตยกรรม Data layer สิทธิ์และความปลอดภัย Presentation Build และ config Conventions

ภาพรวม

Enterprise CMS เป็นแอป Desktop แบบ Windows Forms (MDI) สำหรับจัดการเอกสารองค์กร เขียนด้วย C# บน .NET Framework 4.5 และใช้ SQL Server เป็นฐานข้อมูล ผู้ใช้คือพนักงานภายในองค์กรที่ยืนยันตัวตนผ่าน Active Directory

DMS Document Management

จัดการโฟลเดอร์/ไฟล์ที่ผูกกับหน่วยงาน, สิทธิ์, การแชร์, quota, audit, PDPA

KMS Knowledge Management

คลังบทความความรู้ (KB), หมวดหมู่, เวอร์ชัน, import จาก Excel, dashboard

WFE Workflow Engine

ออกแบบ template workflow, อนุมัติตามขั้นตอน, มอบหมายแทน, SLA และรายงาน

RGP Project / Progress

โครงการ, state, task, สมาชิก/บทบาท, ความคืบหน้า และเอกสารแนบผ่าน DMS

ไฟล์จริงเก็บบน network drive ส่วน metadata สิทธิ์ และ log อยู่ใน SQL Server

ฟีเจอร์หลัก

สถาปัตยกรรมและโครงสร้างโปรเจ็ค

ระบบเป็น layered architecture: Presentation → Controllers → Services → Data → SQL Server โดยไม่มี DI container — Program.cs สร้างทุก object เองด้วย constructor injection

Services คือจุดเดียวที่มี business logic ตรวจสิทธิ์ และเขียน audit; Infrastructure ต่อกับระบบภายนอก และถูกใช้ทั้งจาก Services และ Presentation

Data layer และฐานข้อมูล

CMS.Data คุยกับ SQL Server ผ่าน ADO.NET เรียก stored procedure เท่านั้น ไม่มี ORM

  • Repositories — ประมาณ 55 คลาสใน CMS.Data/Repositories/ มี interface คู่กันใน Interfaces/ ครอบคลุม DMS, KMS, WFE และ RGP
  • Domain models — อยู่ใน CMS.Domain/Models และ Enums ไม่พึ่งพา project อื่น
  • SQL scripts — CMS.Data/Scripts/NNN_Description.sql รันด้วยมือตามลำดับ เพิ่มไฟล์ใหม่ด้วยเลขถัดไป (ล่าสุดคือ 072) ห้ามใช้เลขซ้ำหรือเรียงใหม่ ส่วน 001–070 ถูกลบออกจาก working tree แล้วและดูย้อนได้จาก git history
  • Script แก้ข้อมูล — ให้ preview และ rollback เป็นค่าเริ่มต้น จะ commit ก็ต่อเมื่อตั้ง @Commit = 1
  • Audit — บันทึกอยู่ในตาราง audit.AuditLog ใช้พิสูจน์ได้ว่า action ใน UI ทำอะไรจริง

ไฟล์เอกสารจริงเก็บบน network drive ผ่าน NetworkDriveHelper / NetworkShareConnector

ระบบสิทธิ์และความปลอดภัย

PermissionService ตัดสินสิทธิ์แบบ deny-first และไล่ขึ้นไปที่โฟลเดอร์แม่ ถ้าไม่มีรายการใดตรงเลยจะปฏิเสธ (default deny) ลำดับการตรวจที่โฟลเดอร์หนึ่ง:

  1. Manager (3) และ Admin (4) ผ่านทันที เว้นแต่มี DENY ที่ระบุตรง
  2. คัด ACL ที่ตรงกับผู้ใช้: ตาม User, Role (AppRole), Department หรือ Division
  3. มี DENY ที่ตรงกับสิทธิ์ที่ขอ → ปฏิเสธทันที
  4. มี ALLOW → อนุญาต (FullControl ครอบทุกสิทธิ์)
  5. ไม่มีทั้งสอง และไม่ได้ตัด inheritance → ตรวจที่โฟลเดอร์แม่ซ้ำ
  6. ถึงรากหรือถูกตัด inheritance → ปฏิเสธ
Enumค่า
PermissionTypeRead=1, Write=2, Delete=3, Modify=4, FullControl=5
PrincipalTypeUser=1, Role=2, Department=3, Division=4, Group=5, OrgUnit=6
UserRole (AppRole)Officer=1, SrOfficer=2, Manager=3, Admin=4
ConfidentialityLevelHC=1, SC=2, NC=3, PC=4

ผลการตรวจสิทธิ์ถูก cache ต่อ user+folder และต้อง invalidate เมื่อ ACL หรือข้อมูลผู้ใช้เปลี่ยน การตั้งหรือ propagate สิทธิ์โฟลเดอร์ต้องเป็น Manager ขึ้นไป และทุกครั้งเขียน audit ไฟล์มีสิทธิ์เฉพาะได้ผ่าน FilePermissionService ส่วนการดาวน์โหลดมีชั้นนโยบายแยก (DownloadPolicyService + FileDownloadGate)

การยืนยันตัวตนใช้ Active Directory (AdAuthService) เปิดแอปได้ 3 แบบ: ไม่มี argument (แสดง LoginForm), /u: /p: (credentials จากโปรแกรมอื่น) หรือ /token: (token จากโปรแกรมอื่น)

Presentation layer และกฎโครงสร้าง Form

CMS.Presentation เป็น WinForms MDI มี MDI_Container เป็นหน้าต่างหลัก เมนูโหลดตามสิทธิ์ผู้ใช้ หน้าจอแบ่งตามโมดูลใน Modules/ รวมประมาณ 150 ไฟล์

โฟลเดอร์ตัวอย่างหน้าจอ
Modules/DMSFolderForm, FileUploadForm, ShareManagementForm, SharedWithMeForm, ApprovalInboxForm, AuditLogForm, RecycleBinForm, OrgStructureForm, PdpaConsentDialog
Modules/KMSKBMainForm, KBEditorDialog, ArticleViewerForm, KBCategoryForm, KBImportWizardForm, KBDashboardForm
Modules/WFEWorkflowDesignerForm, WorkflowCreateTemplateWizard, WorkflowDashboardForm, WorkflowMonitorForm, SLAReportForm, WorkflowDelegationForm
Modules/RGPFrm_Project_List, Frm_Project_Detail, Frm_Project_Task_List, Frm_Task_Dashboard, Frm_Project_Progress_Update

หน้าใหญ่ของ WFE ใช้ MVP (Modules/WFE/Presenters/ คู่กับ interface I*View) หน้าเล็กเป็น code-behind ส่วน DMS, KMS และ RGP เรียก logic ผ่าน CMS.Controllers

กฎไฟล์ Form (บังคับใช้เคร่งครัด)

  • ทุก Form ต้องมี *.Designer.cs แยก คู่กับ .resx
  • ห้าม new Control(), ห้ามประกาศ field ของ control, ห้าม Controls.Add() / SuspendLayout() / BeginInit() ใน code-behind
  • code-behind เก็บเฉพาะ logic และ event handler
  • ฟอร์มเก่าที่ยังไม่มี Designer (RecycleBinForm, UserAccessForm, UserManagementForm, FilePreviewPanel) อย่าใช้เป็นแบบ และควรแยก Designer เมื่อแก้ไขมาก

Build, test และ configuration

Build บน Windows ด้วย MSBuild ของ Visual Studio 2022 (ไม่ได้อยู่ใน PATH) ให้รันจาก PowerShell:

& "C:\Program Files\Microsoft Visual Studio\2022\Professional\MSBuild\Current\Bin\MSBuild.exe" CMS.sln /p:Configuration=Debug /nologo /v:minimal
nuget restore CMS.sln   # ถ้า package หาย
  • ถ้าแอปเปิดอยู่ CMS.Presentation.exe จะถูก lock — compile-check ด้วย /p:OutDir=$env:TEMP\<dir>\ แทน
  • Solution มี 6 project: Domain, Infrastructure, Data, Services, Controllers, Presentation ทั้งหมด target .NET Framework 4.5
  • Library หลัก: log4net, Newtonsoft.Json, NPOI (Excel), iTextSharp (PDF), BouncyCastle, BCrypt.Net-Next, SharpZipLib
  • Test — ตอนนี้ไม่มี automated test (โปรเจ็ค CMS.Tests เดิมถูกลบใน commit 05a581d)

Configuration — ConfigManager อ่าน JSON จากตัวแปรสภาพแวดล้อม CMS_CONFIG_PATH ถ้าไม่มีจะใช้ไฟล์กลาง cms_config.json บน network share (CMS_Central_Configs) ไม่ได้อ่านจาก app.config connection string อยู่ที่ ConnectionStrings.CmsDb ค่าอื่นอ่านจาก AppSettings แล้วค่อยไปหาในตาราง SystemConfig ในฐานข้อมูล อย่าคัดลอก credential ไปที่อื่น

Startup — Program.cs สร้าง repository/service ทุกตัว → login ผ่าน AD → ลงทะเบียนผู้ใช้ใหม่ → ขอความยินยอม PDPA → สร้าง UserContext → เปิด MDI_Container

Conventions และเอกสารอ้างอิง

  • Soft delete — ใช้ IsDeleted + DeletedDate ผ่าน SoftDelete() เว้นแต่ต้องลบจริง
  • Audit — ทุก mutation ใน Service ต้องเขียน IAuditService และ log เป็น append-only
  • UserContext — ทุก method ใน Service รับ UserContext และตรวจสิทธิ์ผ่าน IPermissionService
  • Domain model — มี property alias (FolderId ↔ FolderID) และ property สำหรับ UI ที่ Service เติมให้
  • Confidentiality — เก็บเป็น int ใน DB ในโค้ดใช้ property ConfidentialityLevelEnum
  • ตั้งชื่อ — DTO เป็น <Action><Entity>Request / <Entity>Result, private field เป็น _camelCase
  • สไตล์โค้ด — C# 5 ตาม .NET 4.5 ห้ามใช้ API ที่ใหม่กว่านั้น
  • เพิ่ม service/repository — ต้อง wire เองใน Program.cs
  • Git — อย่า stage bin/, obj/, .vs/
