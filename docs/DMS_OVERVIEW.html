คู่มือการตั้งค่าสิทธิ์การเข้าใช้งาน DMS

สำหรับ HR และผู้ดูแลระบบ · ระบบจัดการเอกสาร (DMS) ใน Core Management System · ฉบับ 12 ตุลาคม 2026
สรุป ข้อมูลพนักงาน Level พนักงาน / ระดับความลับ บทบาทในระบบ Authority Config การมองเห็นหน่วยงาน สิทธิ์รายโฟลเดอร์ การดาวน์โหลด ผู้อนุมัติ การแชร์ การตั้งค่ามีผลเมื่อไร สถานการณ์ตัวอย่าง

1สรุปภาพรวม

สิทธิ์ใน DMS ส่วนใหญ่ได้มาจาก ตำแหน่ง แผนก ฝ่าย และ Level ของพนักงาน ข้อมูล HR ที่ถูกต้องจึงทำให้พนักงานได้สิทธิ์ถูกต้องเกือบทั้งหมดโดยไม่ต้องตั้งค่ารายคน

ระบบตัดสินว่าใครทำอะไรได้จาก 4 แหล่ง:

ดูแลโดย HRข้อมูลพนักงาน

ตำแหน่ง แผนก ฝ่าย และสถานะการทำงานดึงจาก HR ตอน login ส่วน Level ต้องนำเข้าหรือแก้ไขในระบบ

ดูแลโดย Adminบทบาทในระบบ

Officer, Senior Officer, Manager หรือ Admin กำหนดว่าเห็นหน่วยงานไหนและข้ามขั้นตอนอนุมัติได้แค่ไหน

ดูแลโดย Admin ร่วมกับ HRAuthority Config

ตารางที่บอกว่าตำแหน่ง/แผนก/ฝ่ายใด ดู เพิ่ม แก้ไข อนุมัติ ดาวน์โหลด เอกสารระดับความลับใดได้

ดูแลโดยหัวหน้า / Adminสิทธิ์เพิ่มเติมรายกรณี

สิทธิ์รายโฟลเดอร์ สิทธิ์ดาวน์โหลดรายคน และการแชร์ไฟล์ ใช้เมื่อมีข้อยกเว้น

2ข้อมูลพนักงานที่ HR ต้องดูแลให้ถูกต้อง

ระบบไม่ได้ให้ใครกรอกข้อมูลเหล่านี้เองใน DMS ระบบดึงจากข้อมูล HR ถ้าข้อมูลต้นทางผิด สิทธิ์ก็จะผิดตาม

ข้อมูลระบบนำไปใช้ทำอะไรถ้าข้อมูลผิดจะเกิดอะไร
ตำแหน่งใช้จับคู่ Authority Config เมื่อตั้งค่าเฉพาะ Level ไว้ไม่ตรงกับพนักงานได้สิทธิ์ของตำแหน่งอื่น หรือไม่ได้สิทธิ์ตามที่ควรได้
แผนกใช้ร่วมกับ Level เพื่อจับคู่ Authority Config เป็นลำดับแรก, ใช้กับสิทธิ์ที่ให้ทั้งแผนก และใช้หาเจ้าของคำขออนุมัติได้ชุดสิทธิ์ผิดแผนก เห็นโฟลเดอร์เดิม หรือคำขออนุมัติไปผิดคน
ฝ่ายเป็นตัวเลือกสำรองของ Authority Config, ใช้กับสิทธิ์ที่ให้ทั้งฝ่าย และใช้หาผู้อนุมัติระดับฝ่ายได้สิทธิ์หรือเส้นทางอนุมัติของฝ่ายอื่น
Level (1A, 1B, 2A … 4B)ใช้จับคู่ Authority Config ร่วมกับแผนก และใช้เรียงลำดับผู้อนุมัติคำขอดาวน์โหลดเมื่อไม่ได้ตั้งผู้อนุมัติไว้ได้ชุดสิทธิ์ไม่ตรงระดับ หรือไม่พบผู้อนุมัติที่เหมาะสมและต้องส่งต่อให้ Admin
สถานะการทำงานบัญชีที่ปิดใช้งานจะ login ไม่ได้คนที่ลาออกแล้วยังเข้าระบบได้
Level ต่างจากข้อมูลอื่น: ตำแหน่ง แผนก และฝ่ายจะอัปเดตจาก HR ทุกครั้งที่ login แต่ Level ไม่อัปเดตอัตโนมัติ ต้องนำเข้าผ่านหน้า นำเข้า Level และสิทธิ์จาก Excel หรือแก้ในหน้าจัดการผู้ใช้

3ทำความเข้าใจ Level พนักงานและระดับความลับ

สองคำนี้ไม่ใช่เรื่องเดียวกัน: Level พนักงาน เช่น 1A–4B บอกระดับของคน ส่วนระดับความลับ เช่น 1HC–4PC บอกระดับของเอกสาร ห้ามนำรหัสสองชุดนี้มาใช้แทนกัน

Level พนักงาน (1A–4B)

Level เป็นรหัสลำดับระดับงานของพนักงาน ระบบเรียงจากต่ำไปสูงดังนี้:

ลำดับจากต่ำไปสูงระบบนำไปใช้อย่างไรสิ่งที่ HR ต้องเข้าใจ
1A → 1B → 2A → 2B → 3A → 3B → 4A → 4Bใช้จับคู่ชุดสิทธิ์ใน Authority Config และใช้หาคนที่ Level สูงกว่าผู้ขอเพื่ออนุมัติดาวน์โหลดในกรณีสำรองชื่อระดับและการเทียบกับตำแหน่งจริงเป็นนโยบายของบริษัท ระบบรู้เฉพาะรหัสและลำดับ
  • Level สูงกว่าไม่ได้แปลว่าได้สิทธิ์มากกว่าอัตโนมัติ สิทธิ์ดู เพิ่ม แก้ไข อนุมัติ และดาวน์โหลด ต้องกำหนดไว้ใน Authority Config
  • พนักงาน Level เดียวกันสามารถมีสิทธิ์ต่างกันได้ หากอยู่คนละแผนกและตั้ง Config แบบ Level + แผนก
  • ถ้าไม่ได้ตั้งผู้อนุมัติดาวน์โหลดประจำแผนก ระบบจึงค่อยใช้ Level เลือกคนในแผนกเจ้าของไฟล์ที่สูงกว่าผู้ขอ แล้วต่อท้ายด้วย Admin
  • Level ไม่ใช่ Role: พนักงาน Level 4B อาจยังเป็น Officer และพนักงาน Level ต่ำกว่าอาจเป็น Manager ได้ ถ้า Admin ตั้ง Role เช่นนั้น

ตัวอย่างผลของ Level (เพื่ออธิบายหลักการ)

สถานการณ์ผลที่เกิดขึ้น
พนักงานบัญชี Level 2A และมี Config “2A + แผนกบัญชี”ระบบใช้ชุดสิทธิ์ของ 2A + แผนกบัญชี
พนักงานบัญชี Level 2A แต่ไม่มี Config แบบ Level + แผนก และมี Config “2A” ส่วนกลางระบบใช้ชุดสิทธิ์ของ Level 2A ส่วนกลาง
ไม่มี Config ที่ตรงกับ Level แต่มี Config ตามตำแหน่งระบบถอยไปใช้ชุดสิทธิ์ตามตำแหน่ง
ผู้ขอ Level 2A ขออนุมัติดาวน์โหลดและแผนกไม่ได้ตั้งผู้อนุมัติไว้ระบบเสนอผู้อนุมัติในแผนกเจ้าของไฟล์ที่สูงกว่า 2A โดยเริ่มจากระดับที่ใกล้ที่สุด เช่น 2B ก่อน 3A

ตัวอย่างนี้อธิบายวิธีทำงานของระบบ ไม่ใช่การกำหนดว่าตำแหน่งใดต้องเป็น Level ใด

ระดับชั้นความลับของเอกสาร (1HC–4PC)

ทุกโฟลเดอร์มีระดับชั้นความลับ 1 ใน 4 ระดับ และ Authority Config จะกำหนดสิทธิ์แยกกันในแต่ละระดับ

กล่องชื่อกฎ Download / Shareหมายเหตุ
1HCHigh Confidential — ลับมากมีขั้นตอนอนุมัติแชร์ให้คนนอกองค์กรไม่ได้
2SCSemi Confidential — ลับมีขั้นตอนอนุมัติใช้ผู้อนุมัติตามแผนก/ฝ่ายเจ้าของเอกสาร
3NCNormal Confidential — ใช้ภายในไม่ต้องขออนุมัติผู้ใช้ยังต้องมีสิทธิ์เข้าถึงเอกสาร
4PCPublic Confidential — เปิดเผยได้ไม่ต้องขออนุมัติผู้ใช้ยังต้องมีสิทธิ์เข้าถึงเอกสาร
หลักจำง่ายสำหรับ HR: การอนุมัติ Download และ Share ใช้เฉพาะกล่อง 1HC–2SC ส่วนกล่อง 3NC–4PC ดำเนินการได้ทันทีเมื่อผู้ใช้มีสิทธิ์เข้าถึงรายการนั้น

โครงสร้างโฟลเดอร์เรียงตามองค์กร: หน่วยงาน (คณะกรรมการ / ฝ่าย / แผนก) แล้วแบ่งเป็นโฟลเดอร์ 4 ระดับความลับ ระดับความลับของโฟลเดอร์ชั้นบนสุดถูกล็อกไว้ เปลี่ยนไม่ได้

4บทบาทในระบบ (Role)

พนักงานทุกคนที่ login ครั้งแรกจะได้บทบาท Officer อัตโนมัติ Admin เปลี่ยนบทบาทได้ในหน้าจัดการผู้ใช้

ให้บทบาท Manager เฉพาะคนที่ต้องดูแลสิทธิ์ของหน่วยงานจริง เพราะ Manager เปิดโฟลเดอร์ในหน่วยงานที่มองเห็นได้เกือบทั้งหมด

5Authority Config — หัวใจของการกำหนดสิทธิ์

หน้า Authority Config คือตารางที่บอกว่า Level / ตำแหน่ง / แผนก / ฝ่ายใด ทำอะไรกับเอกสารระดับความลับใดได้ แต่ละกลุ่ม Config มีช่องสิทธิ์แยกตามระดับความลับ โดยช่อง อนุมัติ ใช้เฉพาะ 1HC และ 2SC

ความหมายของแต่ละสิทธิ์

สิทธิ์มีผลอย่างไร
ดูเปิดโฟลเดอร์และดูไฟล์ในระดับความลับนั้นได้
เพิ่มอัปโหลดไฟล์หรือสร้างโฟลเดอร์ย่อยในระดับนั้นได้
แก้ไขเปลี่ยนชื่อ ลบ หรือย้ายไฟล์/โฟลเดอร์ในระดับนั้นได้ (การย้ายต้องมีสิทธิ์เพิ่มหรือแก้ไขทั้งต้นทางและปลายทาง)
อนุมัติมีสิทธิ์เป็นผู้อนุมัติคำขอ Download/Share ของ 1HC หรือ 2SC ในแผนก/ฝ่ายของตัวเอง สำหรับ 3NC และ 4PC ไม่ต้องกำหนดสิทธิ์นี้
ดาวน์โหลดบันทึกไฟล์ระดับนั้นลงเครื่องได้ทันทีโดยไม่ต้องขออนุมัติ

ตัวอย่างสมมติเพื่ออธิบายเท่านั้น ไม่ใช่ค่าที่ตั้งไว้จริง

ระบบเลือกแถวที่ใช้กับพนักงานอย่างไร

  1. หา Config ที่ตรงกับ Level + แผนก ของพนักงานก่อน
  2. ถ้าไม่มี ใช้ Config ที่ตรงกับ Level โดยไม่จำกัดแผนก
  3. ถ้าไม่มี ใช้ Config ที่ตรงกับ ตำแหน่ง
  4. ถ้าไม่มี ใช้ Config ที่ตรงกับ แผนก
  5. ถ้ายังไม่มี ใช้ Config ที่ตรงกับ ฝ่าย ถ้าไม่ตรงเลย พนักงานจะไม่ได้สิทธิ์จาก Authority Config (ยังเข้าถึงได้ผ่านสิทธิ์รายโฟลเดอร์หรือการแชร์)
Config ที่เฉพาะกว่าใช้แทน Config สำรองทั้งชุด: ระบบไม่ได้รวมสิทธิ์จากทุกแถวเข้าด้วยกัน เช่น ถ้าพบ Level + แผนกแล้ว ระบบจะไม่บวกสิทธิ์จากตำแหน่งหรือฝ่ายให้อีก จึงต้องกำหนดสิทธิ์ของ Config ที่ถูกเลือกให้ครบทั้ง 4 ระดับความลับ

การนำเข้าจาก Excel

Admin นำเข้าตารางอำนาจ (matrix ตำแหน่ง × สิทธิ์) จากไฟล์ Excel ได้ที่หน้า นำเข้า Level และสิทธิ์จาก Excel ระบบจะแสดงตัวอย่างและข้อผิดพลาดก่อนบันทึก (เช่น ตำแหน่งซ้ำ หรือมีสิทธิ์อนุมัติแต่ไม่มีสิทธิ์ดู) และเลือกได้ว่าจะอัปเดต Level ของพนักงานไปพร้อมกันหรือไม่

ให้ HR ส่งไฟล์ Excel ตาม template ให้ Admin นำเข้า แทนการแก้ทีละแถว ช่วยให้ข้อมูลตรงกับเอกสารอำนาจอนุมัติของบริษัท

6การมองเห็นหน่วยงาน

ในหน้าต่างโฟลเดอร์ พนักงานจะเห็นเฉพาะต้นไม้ของหน่วยงานที่ตัวเองมองเห็นได้

  • ค่าเริ่มต้น เป็นไปตามบทบาท (ดูตารางในข้อ 4)
  • กำหนดรายคน ที่หน้า จัดการสิทธิ์การเข้าถึง เมื่อกำหนดแล้วจะใช้รายการนี้แทนค่าเริ่มต้นทั้งหมด เช่น ให้เจ้าหน้าที่ตรวจสอบภายในเห็นหลายฝ่าย

การมองเห็นหน่วยงานเป็นแค่ "เห็นในรายการ" การเปิดโฟลเดอร์ยังต้องมีสิทธิ์ดูจาก Authority Config หรือสิทธิ์รายโฟลเดอร์

7สิทธิ์รายโฟลเดอร์ (ข้อยกเว้น)

ใช้เมื่อต้องการให้หรือห้ามสิทธิ์เฉพาะโฟลเดอร์ นอกเหนือจาก Authority Config Manager หรือ Admin ตั้งได้ที่หน้า ตั้งค่า Folder

  • ให้สิทธิ์กับ คนใดคนหนึ่ง, บทบาท, ทั้งแผนก หรือ ทั้งฝ่าย ได้
  • ระดับสิทธิ์: อ่าน, เขียน, ลบ, แก้ไข, ควบคุมทั้งหมด
  • สิทธิ์ที่ตั้งไว้ที่โฟลเดอร์แม่จะ ส่งต่อไปยังโฟลเดอร์ย่อย อัตโนมัติ เว้นแต่ตัดการสืบทอดไว้
  • ห้าม (Deny) ชนะทุกอย่าง ถ้าตั้งห้ามคนใดไว้ คนนั้นจะไม่ได้สิทธิ์จากการตั้งค่ารายโฟลเดอร์ แม้จะได้รับอนุญาตผ่านบทบาท แผนก หรือฝ่ายก็ตาม
  • ถ้าไม่มีสิทธิ์จากทางใดเลย ระบบจะ ไม่ให้เข้า เป็นค่าเริ่มต้น

8การดาวน์โหลดไฟล์

การ เปิดดู ไฟล์ยังใช้สิทธิ์ดูตามปกติ ส่วนการ บันทึกไฟล์ลงเครื่อง แยกเป็น 2 กรณีตามกล่องของเอกสาร

กล่อง 3NC–4PC

ผู้ใช้ที่มีสิทธิ์เข้าถึงไฟล์สามารถดาวน์โหลดได้ทันที ไม่ต้องสร้างคำขอและไม่ต้องรอผู้อนุมัติ

กล่อง 1HC–2SC

ระบบตรวจสิทธิ์ตามลำดับต่อไปนี้ ข้อแรกที่ผ่านคือคำตอบ:

  1. เป็น Admin → ดาวน์โหลดได้ทันที
  2. มี สิทธิ์ดาวน์โหลดรายคน ครอบ 1HC หรือ 2SC (ตั้งที่หน้า สิทธิ์ดาวน์โหลดรายคน) → ได้ทันที
  3. ได้รับ การแชร์ไฟล์ที่อนุญาตให้ดาวน์โหลด และการแชร์ยังไม่หมดอายุ → ได้ทันที
  4. ตำแหน่งมีสิทธิ์ ดาวน์โหลด ใน Authority Config สำหรับระดับนี้ → ได้ทันที
  5. มี คำขอที่อนุมัติแล้ว และยังไม่ได้ใช้ → ได้ (1 คำขอ ใช้ดาวน์โหลดได้ 1 ครั้ง)
  6. ไม่เข้าข้อใดเลย → ต้องส่งคำขออนุมัติ ผู้ขอติดตามสถานะได้ที่ คำขอดาวน์โหลดของฉัน

9ใครเป็นผู้อนุมัติ

เฉพาะคำขอ Download/Share ของกล่อง 1HC–2SC เท่านั้นที่เข้า Approval Inbox — รายการรออนุมัติ ระบบเลือกผู้อนุมัติจาก แผนก/ฝ่ายที่เป็นเจ้าของไฟล์ ไม่ใช่แผนกของผู้ขอ ส่วน 3NC–4PC ไม่มีรายการรออนุมัติ

คำขอดาวน์โหลด

  1. ถ้า Admin ตั้งผู้อนุมัติไว้ที่หน้า ตั้งค่าผู้อนุมัติ (ดาวน์โหลด / แชร์ไฟล์) ของแผนกหรือฝ่ายเจ้าของไฟล์ → ใช้รายชื่อนี้เท่านั้น
  2. ถ้าไม่ได้ตั้งไว้ → พนักงานในแผนกเจ้าของไฟล์ที่มี Level สูงกว่าผู้ขอ พร้อม Admin ทุกคนต่อท้าย

คำขอแชร์

  1. ถ้าตั้งผู้อนุมัติการแชร์ไว้ในหน้าเดียวกัน → ใช้รายชื่อนั้น
  2. ถ้าไม่ได้ตั้งไว้ → คนในแผนกเจ้าของโฟลเดอร์ที่มีสิทธิ์ อนุมัติ ใน Authority Config สำหรับระดับความลับนั้น
  3. ถ้าแผนกไม่มีใคร → ใช้คนในฝ่ายแม่ที่มีสิทธิ์อนุมัติ
  4. ถ้ายังไม่มี → Admin

ผู้ขอจะไม่ถูกเลือกเป็นผู้อนุมัติคำขอของตัวเอง

ถ้าต้องการให้คำขอไปถึงคนที่ถูกต้องเสมอ ให้ตั้งผู้อนุมัติของทุกแผนกไว้ในหน้า ตั้งค่าผู้อนุมัติ (ดาวน์โหลด / แชร์ไฟล์) และดูแล Level ของพนักงานให้ถูกต้อง

10การแชร์ไฟล์

แชร์ภายในองค์กร

  • แชร์ให้รายบุคคล บทบาท กลุ่ม หรือทั้งแผนก และกำหนดได้ว่าให้ดาวน์โหลดหรือไม่
  • ตั้งวันหมดอายุได้ไม่เกิน 1 ปี และย้อนหลังไม่ได้
  • 1HC–2SC: ใช้ขั้นตอนขออนุมัติก่อนผู้รับเข้าถึง โดยเลือกผู้อนุมัติจากหน่วยงานเจ้าของเอกสาร
  • 3NC–4PC: แชร์มีผลทันที ไม่ต้องส่งคำขออนุมัติ
  • การเปลี่ยนสิทธิ์ Share ของ 1HC–2SC ต้องขออนุมัติใหม่ ส่วน 3NC–4PC บันทึกแล้วมีผลทันที เจ้าของปิดการแชร์ก่อนหมดอายุได้ที่หน้า จัดการการแบ่งปัน

แชร์ให้คนนอกองค์กร

  • สร้างเป็นลิงก์ ตั้งรหัสผ่านและจำนวนครั้งดาวน์โหลดได้ อายุไม่เกิน 90 วัน
  • เอกสารระดับ 1HC แชร์ออกนอกองค์กรไม่ได้ รวมถึงโฟลเดอร์ที่มีไฟล์ 1HC อยู่ข้างใน
  • เอกสารระดับ 2SC ลิงก์ใช้ได้หลังได้รับอนุมัติแล้วเท่านั้น
  • เอกสารระดับ 3NC–4PC ลิงก์มีผลทันที ไม่ต้องรออนุมัติ
แม้ 3NC–4PC ไม่ต้องอนุมัติ ผู้แชร์ยังต้องมีสิทธิ์เข้าถึง/แชร์รายการนั้น และระบบยังบันทึกผู้แชร์ ผู้รับ วันหมดอายุ และกิจกรรมไว้ใน Audit Log

11การตั้งค่ามีผลเมื่อไร และตรวจสอบอย่างไร

สิทธิ์จาก Authority Config คำนวณ ตอนพนักงาน login ถ้าแก้ Authority Config, ตำแหน่ง หรือแผนกระหว่างที่พนักงานใช้งานอยู่ ให้พนักงานปิดโปรแกรมแล้วเปิดใหม่ สิทธิ์ใหม่จึงจะมีผลครบ

สิทธิ์รายโฟลเดอร์และสิทธิ์ดาวน์โหลดรายคนมีผลทันทีหลังบันทึก ส่วน Share ของ 3NC–4PC มีผลทันที แต่ Share ของ 1HC–2SC มีผลหลังผ่านการอนุมัติ

หน้าจอสำหรับตรวจสอบ

หน้าจอใช้ทำอะไร
ตรวจสอบสิทธิ์ผู้ใช้เลือกพนักงาน 1 คน แล้วดูว่าได้สิทธิ์อะไร มาจากแหล่งไหน ใช้หาสาเหตุเมื่อมีคนแจ้งว่าเข้าไม่ได้
ตรวจสอบสิทธิ์ตามหน่วยงานรายงานสิทธิ์ของพนักงานทุกคนแยกตามหน่วยงาน ใช้ทบทวนสิทธิ์ประจำงวด
สิทธิ์ของฉันพนักงานดูสิทธิ์ของตัวเองได้ (เปิดหน้านี้แล้วระบบจะดึงสิทธิ์ล่าสุดให้ด้วย)
จัดการข้อมูล Master โครงสร้างองค์กรและตำแหน่งตรวจและแก้ข้อมูลหน่วยงานและตำแหน่งที่ระบบใช้ นำเข้าจาก Excel ได้

ทุกการเปลี่ยนสิทธิ์ถูกบันทึกใน Audit Log (ใคร ทำอะไร เมื่อไร) ลบหรือแก้ไขย้อนหลังไม่ได้

12สถานการณ์ตัวอย่าง

พนักงานใหม่เริ่มงานHR บันทึกตำแหน่ง แผนก ฝ่าย และ Level ให้ครบ เมื่อพนักงาน login ครั้งแรก ระบบจะสร้างบัญชีเป็น Officer ให้ขอความยินยอม PDPA แล้วให้สิทธิ์ตาม Authority Config ของตำแหน่งนั้นทันที ไม่ต้องตั้งค่าเพิ่ม (ถ้าตำแหน่งนั้นมีอยู่ใน Authority Config แล้ว)
พนักงานย้ายแผนกหรือเลื่อนตำแหน่งHR แก้ข้อมูลต้นทาง แล้วให้พนักงาน login ใหม่ สิทธิ์จะเปลี่ยนตามตำแหน่งใหม่ อัปเดต Level ด้วยถ้าเปลี่ยน และตรวจสิทธิ์รายโฟลเดอร์หรือการมองเห็นหน่วยงานที่เคยให้ไว้เป็นรายคน เพราะสิทธิ์เหล่านั้นไม่ได้ถูกถอนอัตโนมัติ
มีตำแหน่งใหม่ในโครงสร้างเพิ่มตำแหน่งในข้อมูล Master แล้วเพิ่มแถวของตำแหน่งนั้นใน Authority Config (หรือนำเข้า Excel ใหม่) ถ้าไม่เพิ่ม ระบบจะใช้แถวของแผนกหรือฝ่ายแทน และถ้าไม่มีเลยพนักงานจะไม่ได้สิทธิ์
พนักงานลาออกปิดใช้งานบัญชี บัญชีที่ปิดจะ login ไม่ได้ ควรตรวจและปิดการแชร์ที่พนักงานคนนั้นเคยสร้างไว้ในหน้า จัดการการแบ่งปัน ด้วย
ต้องให้คนหนึ่งดาวน์โหลดเอกสารลับได้โดยไม่ต้องขออนุมัติทุกครั้งตั้งที่หน้า สิทธิ์ดาวน์โหลดรายคน เลือกระดับความลับที่อนุญาต ไม่ต้องเปลี่ยนตำแหน่งหรือบทบาท
พนักงานดาวน์โหลดไฟล์กล่อง 3NC หรือ 4PCถ้าพนักงานมีสิทธิ์เปิดไฟล์ ระบบให้ดาวน์โหลดได้ทันที ไม่สร้างคำขอใน Approval Inbox
พนักงานแชร์ไฟล์กล่อง 3NC หรือ 4PCเมื่อพนักงานมีสิทธิ์แชร์ การแชร์ภายในหรือ Share Link มีผลทันที ส่วน 1HC–2SC ใช้กฎอนุมัติ และ 1HC ห้ามแชร์ออกนอกองค์กร
พนักงานแจ้งว่าเปิดโฟลเดอร์ไม่ได้ใช้หน้า ตรวจสอบสิทธิ์ผู้ใช้ ดูว่าตำแหน่งตรงกับ Authority Config หรือไม่ มีการตั้งห้าม (Deny) ไว้หรือไม่ และพนักงาน login ใหม่หลังเปลี่ยนข้อมูลแล้วหรือยัง
คู่มือการตั้งค่าสิทธิ์การเข้าใช้งาน DMS · จัดทำจากกฎที่ใช้งานจริงในระบบ ณ วันที่ 12 ตุลาคม 2026 · ชื่อเมนูในโปรแกรมอาจต่างจากชื่อหน้าจอในเอกสารนี้เล็กน้อย
